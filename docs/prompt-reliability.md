# 发送可靠性与草稿

输入内容按项目路径和对话 ID 保存到本地。切换对话、刷新窗口，或重新打开同一已保存对话时恢复对应草稿。未落盘的空对话在应用重启后可能获得新 ID；目前不把旧空对话草稿自动迁移到新对话。本地存储不可用时仍保留内存草稿，但不能保证跨刷新恢复。

发送前同步锁定本次提交，显示“正在发送”。等待结果时仍可编辑下一条草稿，确认接收后不会覆盖这些新内容。

- 明确未接收：保留完整原文，提供“重试发送”“放回输入框”“丢弃”。连续点击重试只提交一次；放回输入框时保留已有草稿。
- 接收结果不明确：连接异常或发送中刷新窗口后显示“发送结果待确认”，保留原文，不自动重发，也不提供直接重试。核对对话后可关闭提示。
- 已接收后的模型或工具执行失败：沿用原有停止、错误提示与助手重建流程，不重新提交用户消息，以免重复执行操作。

发送 IPC 必须携带 `sessionId`。主进程在等待模型切换完成后核对当前对话，不把迟到请求发送到另一个对话。迟到的发送结果只更新原对话的发送记录。

验证：`pnpm probe:prompt-reliability` 覆盖快速提交/重试、失败原文保留、并发输入、快照气泡去重、对话/项目隔离、迟到回复、草稿恢复和结果不明时禁止重试；已加入 `probe:all`。`probe:session-rebind` 验证主进程拒绝旧对话请求。
