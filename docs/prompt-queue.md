# 运行中的待发送队列

助手运行时，输入框仍可输入；Enter 或发送按钮将消息加入当前对话的队列。停止按钮独立显示。每条消息在上一项任务完全结束后发送，最多保留 20 条待发送消息，不会在当前任务中途插入指令。

- **查看、编辑、取消**：输入框上方展示原文与顺序。开始编辑会暂停后续发送；保存后点击“继续队列”。已经开始发送的消息不能再编辑或取消，应使用停止按钮中止当前任务。
- **暂停与停止**：“暂停后续”只暂停队列；停止按钮会停止当前任务并暂停队列。剩余消息保留，不会因停止而被丢弃。
- **失败**：发送前检查失败时，失败项及后续消息保留，队列暂停。模型运行失败也会暂停后续消息，避免继续依赖失败结果。
- **切换与重启**：队列按项目路径和对话 ID 隔离。切换对话、重建或退出会暂停队列；重新打开同一已保存对话后可继续。刷新 Renderer 不会重复入队。未落盘空对话在应用重启后可能无法再通过侧栏找到，暂不自动迁移它的队列。
- **确认丢失**：入队请求有稳定 ID。若 IPC 确认丢失，“确认入队结果”可使用原 ID 再次提交，不会重复添加已经执行或取消的消息。应用重启前已开始发送、但未完成确认的项目标为“发送结果待确认”，必须核对并移出队列，不能直接重试执行。

## 实现与边界

队列存放在应用私有 `pi-agent/prompt-queues.json`，用临时文件及 rename 原子更新。开始发送前先持久化 `sending` 状态；重启时所有队列默认暂停，`sending` 转为 `uncertain`。记录已使用的 ID，防止迟到请求重新创建已经处理的消息。

主进程管理队列与调度，Renderer 只展示快照并调用白名单 IPC。新增 `agent.queue.add/edit/remove/control` 命令，均校验字段、sender 与当前对话归属；入队、编辑和继续执行还要求工作区至少为 restricted。执行仍经过普通 prompt 的模型/凭据检查与 PermissionManager，不提升工具权限。队列文本是用户输入，可完整显示；不使用工具输出的预览截断。

Pi 0.84.4 原生 follow-up API 支持追加和清空整个队列，未提供稳定消息 ID 的单项编辑/取消接口。本轮使用应用队列：在 `agent_settled` 后先应用待切换模型，再逐条调用普通 prompt。这样保持每项任务独立一轮，Skills 也在实际执行时通过相同的 prompt 路径展开。未接入原生 steering，不改变正在执行任务的指令。

`queue.updated` 事件及 `AgentSnapshot.promptQueue` 包含递增 revision，旧回复不能覆盖新队列。`queue.dispatched` 只在 SDK 接收时生成用户气泡，使用稳定 ID 去重；遇到 delta 乱序仍处理该事件，再通过快照对账。

## 验证

- `pnpm probe:queue`：队列持久化、单项编辑/取消、重试去重、顺序调度、失败暂停、停止与 preflight 竞态、Renderer 草稿/事件对账；已加入 `probe:all`。
- `pnpm probe:session-rebind`：真实 SDK 的会话切换暂停/隔离与旧会话请求拒绝。
- `pnpm probe:queue-ui`：真实 Electron Renderer/preload，使用隔离 userData 与模拟 Main，验证 Enter 入队、独立停止按钮、编辑/取消、暂停/继续及刷新恢复。不读取真实凭据，也不调用模型。
